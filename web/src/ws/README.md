# WebSocket client

Модуль не зависит от React и использует браузерный `WebSocket`. Адрес берётся из
`VITE_WS_ORIGIN` (без завершающего `/`); без переменной используется текущий host
с `ws:` или `wss:`. Access JWT передаётся только вторым элементом
`Sec-WebSocket-Protocol`. Refresh cookie модуль не читает.

`AuthAdapter` и `HistoryAdapter` намеренно узкие: после слияния PR #75 их можно
связать с `refresh`, `listChats` и `getMessageHistory`, не копируя REST-клиент.
При logout вызывающий код сначала вызывает `stop()`, а затем REST logout.
Один экземпляр клиента сериализует refresh внутри себя и ограничивает временные
ошибки тремя попытками по умолчанию. Успешно обновлённый токен не обновляется
снова до 30 секунд стабильного соединения, что исключает цикл 4401/refresh.
Повторный немедленный `4401` переводит клиент в терминальный `auth_failed` с
`authFailure: refreshed_token_rejected`; окончательный отказ и исчерпание
refresh-попыток также имеют отдельные диагностические причины.
Координация ротации
refresh token между вкладками требует общего frontend session coordinator и в
этом модуле не заявлена.

Автоматическая отправка ограничена настраиваемым `maxAutomaticAttempts`
(временное значение по умолчанию — 5), после чего сообщение остаётся `failed` и
может быть повторено явно с тем же `client_msg_id`. Это клиентская защитная
политика, а не часть backend-контракта.

`MockWebSocketServer` — in-memory имитация прикладного протокола для разработки и
Vitest. Она проверяет список предложенных subprotocols и токен, но не проверяет
реальный HTTP Upgrade, TLS, Origin allowlist или криптографию JWT.
