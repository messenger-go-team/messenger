# Проверки Go

В репозитории используется один корневой Go-модуль:
`github.com/messenger-go-team/messenger`.
Будущие Go-сервисы и общие пакеты входят в этот модуль.

Версия Go указана в `go.mod`. GitHub Actions читает её через
`go-version-file`, поэтому отдельно обновлять версию в workflow не нужно.
Сейчас используется Go **1.27.3** и golangci-lint **v2.15.0**.

## Что запускается

Workflow `.github/workflows/ci.yml` работает для каждого pull request в
`main` и каждого push в `main`. Ограничений по путям нет, чтобы обязательные
проверки запускались и для PR с документацией.

Два задания выполняются параллельно:

- **Go lint**: `golangci-lint run` со стандартным набором линтеров.
- **Go test**: `go test -race -count=1 ./...` с включённым CGO.

Каждое задание ограничено пятью минутами. Включено кеширование Go-модулей
и результатов сборки; ключ учитывает `go.mod` и `go.sum`, когда он появится.
Новый push в ту же ветку PR отменяет устаревший прогон.
Actions закреплены по SHA с указанием версии в комментарии.

Пока добавлен только документационный пакет `doc.go`: тесты проверяют
загрузку пакета и сообщают `[no test files]`. Это подготовка CI, а не
покрытие бизнес-логики. Реальные сервисы и тесты добавляются в следующих задачах.
Файл `go.sum` появится при добавлении внешних зависимостей.

## Локальная проверка

Установите версию Go из `go.mod` и golangci-lint v2.15.0.
Для race detector нужны CGO и C-компилятор; CI использует Linux.
В Windows удобно запускать проверки внутри WSL.

Из корня репозитория:

```bash
go version
go mod download
golangci-lint config verify
golangci-lint run
CGO_ENABLED=1 go test -race -count=1 ./...
```

## Обязательные проверки перед merge

После первого успешного прогона в T03 нужно добавить **Go lint** и
**Go test** в обязательные status checks для `main`.
Оба задания должны успешно завершиться перед merge.

Сам workflow показывает результат проверок, но запрет merge настраивается
отдельно в правилах ветки. Он не включается автоматически при добавлении YAML.
