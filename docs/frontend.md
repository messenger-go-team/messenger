
# Frontend — технические решения

## Назначение

Веб-клиент Messenger реализуется на React и TypeScript.

Основная задача фронтенда — предоставить пользовательский интерфейс для авторизации, работы с личными чатами, просмотра истории сообщений и обмена сообщениями в реальном времени.

Текущий этап T17 ограничен настройкой инфраструктуры фронтенда. Полноценные экраны и интеграции с бэкендом реализуются в отдельных задачах.

## Технологический стек

| Технология | Назначение |
| --- | --- |
| React 19 | Компонентная модель пользовательского интерфейса |
| TypeScript | Статическая типизация и проверка типов |
| Vite 8 | Сервер разработки и production-сборка |
| Tailwind CSS 4 | Utility-first стилизация |
| shadcn/ui | Исходный код переиспользуемых UI-компонентов |
| Base UI | Доступные интерактивные примитивы компонентов |
| Lucide React | SVG-иконки |
| Geist | Шрифт интерфейса |
| ESLint | Статический анализ кода |

## Выбор инструментов

### Vite

Vite выбран как инструмент сборки благодаря быстрому запуску сервера разработки, поддержке React и TypeScript и простой конфигурации.

Для React используется официальный плагин `@vitejs/plugin-react`.

Production-сборка запускается командой:

```bash
npm run build
```

Команда сначала выполняет проверку TypeScript (`tsc -b`), затем сборку Vite.

### TypeScript

TypeScript используется для типизации компонентов, функций и данных приложения.

Настроен alias `@/`, который указывает на директорию `../web/src`.

Пример импорта:

```tsx
import { Button } from "@/components/ui/button"
```

Alias настроен в конфигурациях TypeScript и Vite.

### Tailwind CSS v4

Tailwind CSS подключён через `@tailwindcss/vite`.

Основные стили и дизайн-токены находятся в `../web/src/index.css`.

Tailwind позволяет использовать готовые utility-классы непосредственно в компонентах, сокращая количество отдельных CSS-файлов.

### shadcn/ui

Для пользовательского интерфейса используется shadcn/ui.

Выбрана конфигурация:

- Style: Nova.
- Primitive library: Base UI.
- Base color: Neutral.
- Icons: Lucide.
- CSS variables: enabled.

Конфигурация хранится в `../web/components.json`.

Компоненты добавляются в исходный код проекта и размещаются в `../web/src/components/ui`.

Это позволяет изменять их реализацию и стили под требования дизайна без необходимости поддерживать отдельную библиотеку компонентов.

CLI shadcn установлен как зависимость разработки (`devDependency`).

### Base UI

Base UI предоставляет низкоуровневые интерактивные компоненты с поддержкой доступности.

В сочетании с shadcn/ui используется для создания элементов интерфейса, таких как кнопки, диалоговые окна, меню и другие компоненты.

## Дизайн-токены и тема

Тема приложения определяется CSS-переменными в `../web/src/index.css`.

В конфигурации shadcn/ui предусмотрены токены для:

- Цветов фона и текста.
- Цветов основных и второстепенных элементов.
- Границ и состояний интерфейса.
- Радиусов скругления.
- Шрифтов.

Tailwind использует эти значения через соответствующие utility-классы.

Примеры:

```tsx
<div className="bg-background text-foreground">
  <Button>Начать общение</Button>
</div>
```

При появлении утверждённого дизайна значения токенов могут быть адаптированы без изменения структуры компонентов.

## Структура исходного кода

```text
web/src/
├── components/
│   └── ui/          # UI-компоненты shadcn/ui
├── lib/
│   └── utils.ts     # Общие утилиты
├── App.tsx          # Корневой компонент
├── index.css        # Tailwind CSS и тема
└── main.tsx         # Точка входа приложения
```

Дополнительные директории для страниц, API, состояния приложения и WebSocket-взаимодействия будут добавляться по мере реализации соответствующих задач.

## Локальная разработка

Требования к Node.js для установленного Vite 8:

- `^20.19.0 || >=22.12.0`

Из директории `../web`:

```bash
npm ci
npm run dev
```

Проверка перед Pull Request:

```bash
npm run lint
npm run build
```

Для просмотра production-сборки:

```bash
npm run preview
```

## Зависимости и безопасность

Зависимости фиксируются в `package-lock.json`.

Для проверки известных уязвимостей используются:

```bash
npm audit
npm audit --omit=dev
```

На момент выполнения T17 аудит production-зависимостей не обнаружил известных уязвимостей.

Полный аудит сообщил о предупреждениях в транзитивных зависимостях инструментов разработки, включая shadcn CLI и ESLint.

Принудительное обновление через `npm audit fix --force` не применяется без проверки совместимости.
