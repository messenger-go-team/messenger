# Контакты и поиск: чек-лист MVP

Основание: [auth.yaml](../../../api/openapi/auth.yaml), [history.yaml](../../../api/openapi/history.yaml), SPEC FR-AUTH-6..7, FR-WEB-1..2, [решения #68](https://github.com/messenger-go-team/messenger/issues/68). [Общие правила](README.md). Данные: A/B/C и существующий AB с историей; отдельные наборы поиска Alice_1/Malice_1 и 21+ совпадений общего prefix; независимые пары A–D/A–E без чата для CONTACT-CL-025 (см. README).

## REST и изоляция

- [ ] CONTACT-CL-001 [P0] GET /contacts с JWT A → 200 `{contacts:[...]}`, весь собственный список без пагинации; каждый элемент соответствует UserSummary, принадлежность определяется по id, обязательного is_contact нет.
- [ ] CONTACT-CL-002 [P1] У нового пользователя пустой список → 200 `{contacts:[]}`, не 204/404.
- [ ] CONTACT-CL-003 [P1] Контакты отсортированы по возрастанию ASCII lower-case username; исходное написание сохраняется, смешанный регистр не нарушает порядок.
- [ ] CONTACT-CL-004 [P0] PUT /contacts/{B} от A → пустой 204, B появляется у A ровно один раз; повтор и конкурентные PUT не создают дубль, отвечают 204.
- [ ] CONTACT-CL-005 [P0] После добавления A → B список B не получает обратную запись. Запрос с JWT C возвращает только список C, не A; клиентское состояние после смены аккаунта не показывает список предыдущего пользователя.
- [ ] CONTACT-CL-006 [P1] PUT отсутствующего пользователя (валидный UUID) → 404; PUT собственного ID A → 422; PUT с некорректным UUID → 422. Список не меняется.
- [ ] CONTACT-CL-007 [P0] DELETE /contacts/{B} от A → пустой 204, B исчезает из списка A; список B не меняется.
- [ ] CONTACT-CL-008 [P1] Повтор DELETE, удаление отсутствующей записи, собственного ID и несуществующего пользователя с валидным UUID → пустой 204. Некорректный UUID → 422.
- [ ] CONTACT-CL-009 [P0] GET, PUT и DELETE без JWT/с невалидным/истёкшим JWT → 401 ApiError; нет изменения или раскрытия чужого списка. Каждый метод проверить отдельно.
- [ ] CONTACT-CL-010 [P1] Тела 200/401/404/422 соответствуют OpenAPI; у 204 тело действительно пустое. UI не вызывает JSON.parse для 204.
- [ ] CONTACT-CL-011 [P0] После удаления контакта существующий chat_id, история и права участников сохранены; оба пользователя продолжают переписку без повторного добавления контакта.

## Глобальный API — GET /users/search?prefix=...

- [ ] CONTACT-CL-012 [P1] На отдельном наборе существуют Alice_1 и Malice_1, других совпадений ALICE нет; запрос выполняется от A, отличного от этих пользователей. GET /users/search?prefix=ALICE и повтор с prefix=alice → 200: обязательно присутствует ID Alice_1 с username точно Alice_1, ID Malice_1 отсутствует. Пустая выдача в этом наборе — Fail. Отдельно prefix длиной 1/32 из `[A-Za-z0-9_]` возвращает заранее подготовленные совпадения; UserSummary соответствует схеме.
- [ ] CONTACT-CL-013 [P1] На независимом наборе с 21+ совпадением общего prefix ответ 200 содержит непустой users, не больше 20 записей, все username начинаются с prefix без учёта регистра. Для отдельного prefix с заведомо нулём совпадений → 200 `{users:[]}`. Не смешивать этот массовый набор с положительным примером ALICE из CONTACT-CL-012; порядок глобальной выдачи контрактом не задан.
- [ ] CONTACT-CL-014 [P1] Отсутствующий prefix, пустая строка, длина 33, кириллица, `@`, пробел, дефис → 422 по текущему ограничению. Эти запросы делать напрямую API: UI их не отправляет.
- [ ] CONTACT-CL-015 [P0] Поиск без JWT/с невалидным/истёкшим JWT → 401; refresh cookie без bearer не авторизует поиск.

## Экран контактов и согласованные решения #68

- [ ] CONTACT-CL-016 [P1] «Контакты» доступны отдельным пунктом общей навигации; поиск и начало чата также сохранены в списке чатов T43.
- [ ] CONTACT-CL-017 [P1] Пустой ввод показывает все контакты, не вызывает GET /users/search. После очистки запроса поздний ответ не восстанавливает глобальную выдачу.
- [ ] CONTACT-CL-018 [P1] Непустой ввод локально фильтрует контакты **по подстроке** username без учёта регистра; глобальный блок «Найдено» ищет **по префиксу**. Проверить запрос, совпадающий только в середине имени контакта.
- [ ] CONTACT-CL-019 [P1] Невалидный для глобального API ввод (кириллица, `@`, более 32 символов) не отправляется серверу: отдельная подсказка в «Найдено», прежние результаты скрыты. Локальная фильтрация продолжает работать.
- [ ] CONTACT-CL-020 [P1] Быстрый ввод вызывает debounce; отменённые/устаревшие ответы игнорируются. Ответ старого prefix не заменяет результат нового, в том числе при переходе к невалидному/пустому вводу.
- [ ] CONTACT-CL-021 [P0] Себя в UI не показываем; между показанными отфильтрованными контактами и «Найдено» нет повторных строк по ID. Наличие контакта определяется по всему GET /contacts, а не только отфильтрованным строкам.
- [ ] CONTACT-CL-022 [P1] B — контакт A, имя B совпадает с выбранным prefix; один и тот же ID B приходит из GET /contacts и GET /users/search. В UI B отображается ровно один раз в локальных контактах, исключён из «Найдено»; для строки доступно «Удалить», а не «Добавить». Не использовать недостижимый на согласованных данных вариант «prefix совпал, локальная подстрока — нет». Исключение контактов/себя из UI не требовать от самого API.
- [ ] CONTACT-CL-023 [P1] Есть отдельные состояния загрузки, пустого списка контактов, отсутствия результатов, ошибки с повтором и выполняемого действия; при ошибке сохраняется последний корректный список.
- [ ] CONTACT-CL-024 [P1] Добавление/удаление блокируется на время своего запроса; после успеха список обновляется, после отказа не показывает неподтверждённый результат. Optimistic update не обязателен.
- [ ] CONTACT-CL-025 [P0] Использовать две независимые пары без чата: A–D для входа из контактов (D добавлен A) и A–E для входа из «Найдено» (E не контакт). Перед каждым новым прогоном подтвердить отсутствие чата соответствующей пары в тестовой БД; общий существующий AB не использовать для ожидания 201. Для каждой пары первое «Написать» → POST /chats/personal {"user_id":"<D или E>"}, ответ 201 с новым Chat.id и правильный диалог; повтор из той же точки входа → 200 с тем же Chat.id (chat_id). Для E добавление контакта не требуется и не выполняется автоматически; второго чата нет.
- [ ] CONTACT-CL-026 [P1] Ошибка сети, 401 или отказ создания чата не открывают чужой/несуществующий диалог; видны ошибка и доступное действие восстановления без вечной загрузки.
- [ ] CONTACT-CL-027 [P1] На мобильной, планшетной и десктопной раскладках видны поиск, оба блока и действия строки; доступны клавиатура, фокус и управление без мыши по макетам. Подробные шаги — в T48.

- [ ] CONTACT-CL-028 [P1] Ошибка глобального поиска не скрывает локальные контакты с текущим фильтром; сообщение и повтор относятся только к «Найдено». Старая глобальная выдача не показывается как результат другого ввода.
