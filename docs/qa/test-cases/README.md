## Окружение и данные

Для MVP нужен изолированный стенд auth/history/chat/PostgreSQL и веб-клиент с известным SHA и адресами. Для cookies — HTTPS и реальный браузер; локальный HTTP не подтверждает Secure. Для API/WS негативных запросов использовать клиента, позволяющего задавать заголовки и payload; HTTP-отказ WS-handshake проверять протокольным клиентом, не чтением тела из браузерного WebSocket API.

Общие данные: A/B с отдельными сессиями, посторонний C, чаты AB/AC, свободные username, отсутствующие валидные UUID, контролируемое состояние контактов/read/Later. Индивидуальные предусловия кейса имеют приоритет над общими: для тестов нового чата каждый раз новая пара или сброс данных. В CONTACT-11 используются независимые AD/AE без чата; существующий AB не подходит для проверки 201. Для UI — изолированные browser context A/B и при необходимости две вкладки A. В API-сценариях курсоры не должны изменяться скрытым автоматическим POST /read от параллельно открытого UI.

Для гонок/потерь нужны барьеры commit, подавление ack/new, управление сетью и тестовые часы. Для unread фиксируется исходный last_read_seq, состав чужих/собственных seq и GET /chats до/после. Для Later отдельно управляются часы устройства/TZ и часы БД/server_time: срок выбирает клиент, статус вычисляет сервер. Время устройства само по себе не переводит серверную запись в due.

Удаление цели/чата и отзыв/возврат доступа проверяются тестовыми seed/hooks: наличие пользовательского API удаления не предполагается. При отсутствии стенда, hooks, управляемых часов или необходимой реализации соответствующий прогон — Blocked. Моки подтверждают UI, но не commit/дедупликацию/приватность БД.

Контрольные ширины 360/768/1440 CSS px используются для трёх раскладок; конкретные breakpoints и браузеры уточняются по утверждённым макетам/матрице. Не менять настоящее время рабочей системы без необходимости: использовать часы тестового приложения/контекста.

## Формат, результат и очистка

У каждого кейса есть ID, приоритет, шаги и ожидаемый результат; дополнительные файлы также содержат индивидуальные предусловия. P0 — критический путь, права и сохранность данных; P1 — основные/негативные сценарии; P2 — дополнительные проверки. В наборе параметров каждый вариант выполняется независимо, иначе изменение данных первым вариантом может исказить следующий.

Порядок выполнения: восстановить начальные данные → выполнить шаги → сравнить ответы/состояние UI и БД с ожидаемым → записать фактический результат → очистить тестовые данные. Для API валидировать схемы ответов, а не только статус; пустой 204 не разбирать как JSON. Наличие фразы «Ожидается» не является фактическим результатом.

В отчёте по ID указать дату, SHA, исполнителя, URL стенда, версии клиента/браузера/ОС, тестовые параметры, Passed/Failed/Blocked/Not run и дефекты/доказательства без токенов, паролей и чужих данных. Формат соответствует [шаблону тест-кейса](../../../.github/ISSUE_TEMPLATE/test-case.yml). Статусы в этом документе не менять на Passed до реального прогона.

После каждого кейса удалить созданные тестовые контакты/записи или восстановить seed только в тестовом окружении; для чатов без API удаления использовать отдельные одноразовые пары. Завершить активные fault-hooks, вернуть membership/часы/TZ, закрыть дополнительные вкладки, отозвать тестовые сессии при необходимости. Не сбрасывать production или данные других проверок.

## Покрытие критериев T48

- Регистрация, вход, refresh/logout и негативные запросы: AUTH-01..10, AUTH-14.
- Создание чата и отправка/получение: CHAT-01..03, WS-01..06, MSG-01..05; повтор/восстановление — REC-01..07. Шаги REC-03 учитывают подтверждение через new и REST без client_msg_id; контрактный 503 History и восстановление — HIST-04, UNREAD-07.
- Пустые контакты, CRUD/повторы, чужой список и контрактные ошибки: CONTACT-01..05; сохранение чата — CONTACT-12.
- Подстрока/регистр/prefix, пустой/невалидный ввод, отсутствие результатов, себя/дубли, быстрый ввод/устаревший ответ: CONTACT-05..10, CONTACT-14.
- Новый/существующий чат из контактов/поиска без обязательного добавления: CONTACT-11; сеть/401 и три раскладки/клавиатура — CONTACT-13, CONTACT-15.
- unread_count, собственные сообщения, активный показ/предзагрузка/фон: UNREAD-01..04. Повторы/вкладки, гонки/ошибка — UNREAD-05..07. Недопустимые seq, права и изоляция без message.read — UNREAD-08..12.
- Четыре варианта Later, 19:00/следующий день/TZ, три группы, повтор/перенос/done: LATER-01..08. Напоминания открытого/закрытого приложения — LATER-09..12; переход/context — LATER-13..14.
- Приватность, недоступные/удалённые цели, устаревшее действие, повторный вход: LATER-15..20; три раскладки и контрактные ошибки — LATER-21..22.
