# Проверка маршрутизации Auth

[Snippet](snippets/auth-locations.conf) подключается внутри публичного
`server`, upstream `auth_backend` указывает на внутренний Auth. Полный домен,
TLS и маршрутизация на VPS реализуются в #36.

## Регрессия исходного URI

Публичные locations сохраняют исходный URI через `proxy_pass` без URI.
Вариант с `/contacts/` после имени upstream позволял Nginx превратить
некорректный ID `x%2F..%2F<uuid>` в валидный UUID и выполнить изменение
контактов. Требуется одинаковый `422` напрямую и через внешний Nginx,
без изменения собственного списка ни после PUT, ни после DELETE.

[auth_routing_test.go](auth_routing_test.go) проверяет настоящий Nginx
и Auth по HTTP, включая фактическое состояние контактов. Подготовьте
изолированный тестовый Auth с миграцией и отдельной БД, затем задайте:

- `AUTH_NGINX_TEST_URL`: базовый URL Nginx без пути, например `http://127.0.0.1:18080`.
- `AUTH_DIRECT_TEST_URL`: URL Auth из внутренней сети, например `http://127.0.0.1:18081`.
- `AUTH_INTERNAL_TOKEN`: тот же служебный секрет, что передан тестовому Auth.

Из корня репозитория:

```bash
go test -race -count=1 -run '^TestAuthRouting$' -v ./deploy/nginx
```

Тест создаёт два временных аккаунта через настоящий register/login.
Пользователи остаются в тестовой БД до её сброса. Нужны доступ к обоим URL
и доверенный TLS-сертификат при использовании HTTPS. Без
`AUTH_NGINX_TEST_URL` тест пропускается, Docker из Go-теста не запускается.

Проверяются:

- GET профиля, поиска и списка через Nginx, валидные PUT/DELETE контакта;
- PUT/DELETE с исходным некорректным ID напрямую и через Nginx, включая
  `%2F`, `%2f`, двойное кодирование и нормализацию в другие публичные пути;
  после каждого запроса проверяется список;
- кодированный путь, нормализующийся в `/auth/login`, не выполняет вход;
- внутренний lookup с верным служебным секретом и отказ для пользовательского JWT;
- отказ использовать служебный секрет для публичного профиля;
- недоступность `/internal` через Nginx с верным секретом, включая кодированные
  разделители и переходы из публичных путей.

Клиент не следует redirect, поэтому перенаправление не маскирует результат.
Ответы с credentials и значения секретов не выводятся в отчёт теста.

## Приёмка #36 и #38

Повторить сценарий на итоговой конфигурации Nginx, включая подключённые
rewrite/location, и через внешний HTTPS стенда. Записать SHA сборки и
результат в #38. Локальная проверка snippet не заменяет staging QA.
